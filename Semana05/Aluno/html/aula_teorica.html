1. NumPy: arrays e operações vetorizadas

Exemplo 1 — Array x lista

import numpy as np

precos_lista = [12.5, 2.0, 3.5]
precos_array = np.array([12.5, 2.0, 3.5])

print(type(precos_lista))
print(type(precos_array))
print(precos_array * 2)   # multiplica cada elemento por 2, de uma vez

precos_array * 2 retorna [25. 4. 7.]: o NumPy multiplica cada elemento ao mesmo tempo, sem nenhum for. type(precos_array) mostra numpy.ndarray — o nome ndarray significa "n-dimensional array" (array de N dimensões): nesta semana você só usa arrays 1D (uma sequência simples), mas o NumPy também representa tabelas (2D) e além, sempre com essa mesma classe.

⚠️ Veja como é um erro real do Python: multiplicar uma lista comum por 2 não dá erro — mas também não faz o que parece: 
precos_lista = [12.5, 2.0, 3.5]
print(precos_lista * 2)
[12.5, 2.0, 3.5, 12.5, 2.0, 3.5]
Em vez de dobrar cada preço, o Python repete a lista duas vezes seguidas. Esse é um dos bugs mais traiçoeiros de quem vem de lista pra array: não trava, só faz a coisa errada silenciosamente — sem observar o resultado com atenção, é fácil achar que a conta funcionou.

Exemplo extra — Somar um número: lista dá erro, array não

import numpy as np
try:
    lista = [1, 2, 3, 4, 5]
    print(lista + 1)
except TypeError as e:
    print(f"Erro: {e}")

array = np.array([1, 2, 3, 4, 5])
print(array + 1)

lista + 1 trava de verdade, com TypeError: can only concatenate list (not "int") to list — o Python não sabe como somar um número a uma lista, e nem tenta adivinhar. array + 1 soma 1 em cada posição de uma vez, retornando [2 3 4 5 6] — isso é broadcasting, que você vai ver com mais detalhe mais adiante nesta mesma seção.

Exemplo extra — Nem toda lista vira um array "limpo"

import numpy as np
lista_misturada = [1, "dois", 3.0]
array_misturado = np.array(lista_misturada)

print(array_misturado)
print(array_misturado.dtype)
💡 O NumPy não recusa tipos misturados — ele converte tudo pro tipo mais genérico. Uma lista pode misturar número e texto na mesma variável; um array NumPy não pode: todos os elementos precisam ser do mesmo tipo. Aqui, o resultado é ['1' 'dois' '3.0'], e array_misturado.dtype mostra <U32 (texto Unicode) — texto é o único tipo capaz de representar os três valores originais ao mesmo tempo. É por isso que todo valor lido de um CSV precisa ser convertido com float(...)/int(...) antes de entrar num array: um único valor de texto sobrando no meio de uma coluna numérica faria o array inteiro virar texto.

Exemplo extra — Por que isso importa: velocidade

import numpy as np
import time

numeros_lista = list(range(1, 10_000_001))
numeros_array = np.array(numeros_lista)

inicio = time.time()
soma_lista = sum(numeros_lista)
print(f"Lista: {time.time() - inicio:.4f} segundos")

inicio = time.time()
soma_array = np.sum(numeros_array)
print(f"Array: {time.time() - inicio:.4f} segundos")

Com poucos elementos, a diferença de velocidade entre lista e array é imperceptível. Mas datasets reais têm milhares (ou milhões) de linhas — e aí a diferença fica bem visível: somar com np.sum() sobre o array é geralmente entre 5 e 15 vezes mais rápido que sum() sobre a lista equivalente. É por isso que o NumPy é a ferramenta padrão do mercado para dado numérico em volume.

Exemplo extra — Fatiando um array (slice)

import numpy as np
precos_array = np.array([12.5, 2.0, 3.5, 6.0, 150.0])

print(precos_array[1:4])   # índices 1, 2 e 3 -- NÃO inclui o índice 4
print(precos_array[:3])    # do início até o índice 3 (exclusive) -- os 3 primeiros
print(precos_array[3:])    # do índice 3 até o final
💡 O que é fatiamento (slice)? array[início:fim] devolve um pedaço do array, do índice início até o índice fim — mas sem incluir o fim. Num array de 5 posições (índices 0 a 4), array[1:4] devolve os índices 1, 2 e 3 — três valores, não quatro. Isso não é exclusividade do NumPy: listas comuns, tuplas e até texto já funcionam com essa mesma sintaxe. Dois atalhos úteis: array[:3] significa "do começo até o índice 3, exclusive"; array[3:] significa "do índice 3 até o final".
⚠️ Erro comum: pedir mais índices do que o array tem, tipo precos_array[3:10], não trava — o Python devolve o que existir a partir do índice 3, sem erro nenhum e sem avisar que você pediu mais do que existia: 
print(precos_array[3:10])   # [  6. 150.]  -- igual a precos_array[3:]
Repare a diferença com acessar um índice único fora do intervalo, como precos_array[10], que lança IndexError: index 10 is out of bounds. O slice é tolerante a limites maiores que o array; o acesso direto por índice exige que a posição exista.

Exemplo 2 — Calculando a receita de Janeiro com arrays reais

vendas_papelaria.csv é o arquivo real desta semana — a técnica pra ler é a mesma que você já usou na Semana 04: o módulo csv e o csv.DictReader. Antes de filtrar qualquer coisa, veja como é UM registro do arquivo inteiro, sem filtro nenhum — é assim que você descobre quais colunas existem e como elas se chamam.

import csv

with open("dataset/vendas_papelaria.csv", encoding="utf-8") as arquivo:
    todas_vendas = list(csv.DictReader(arquivo))

print(todas_vendas[0])
# {'produto': 'Caderno', 'categoria': 'Papelaria', 'mes': 'Jan',
#  'preco_unitario': '12.5', 'quantidade_vendida': '30'}

As chaves desse dicionário — produto, categoria, mes, preco_unitario, quantidade_vendida — são exatamente os nomes de coluna que o restante da aula usa pra filtrar e calcular.

Agora que você já sabe que existe uma coluna mes, filtrar por ela faz sentido. Veja como ficam os 6 registros de Janeiro, ainda em formato de dicionário:

import csv

with open("dataset/vendas_papelaria.csv", encoding="utf-8") as arquivo:
    vendas_jan = [linha for linha in csv.DictReader(arquivo) if linha["mes"] == "Jan"]

for registro in vendas_jan:
    print(registro)

Repare que cada valor ainda está em formato texto ('12.5', não 12.5) — é assim que o módulo csv sempre entrega os dados. Agora vamos converter as colunas preco_unitario e quantidade_vendida em arrays NumPy pra calcular a receita.

import csv
import numpy as np

with open("dataset/vendas_papelaria.csv", encoding="utf-8") as arquivo:
    vendas_jan = [linha for linha in csv.DictReader(arquivo) if linha["mes"] == "Jan"]

precos = np.array([float(linha["preco_unitario"]) for linha in vendas_jan])
quantidades = np.array([int(linha["quantidade_vendida"]) for linha in vendas_jan])

receita = precos * quantidades   # multiplicação elemento a elemento, sem for!
print(receita)
# [375. 160. 210. 120. 750. 350.]

Cada valor lido do CSV chega como texto ('12.5', entre aspas) — por isso float(...) e int(...) convertem antes de montar os arrays. precos * quantidades multiplica os dois arrays posição a posição, sem nenhum for escrito no código.

Exemplo extra — Broadcasting e funções estatísticas

precos_com_aumento = precos * 1.10   # aumenta 10% em todos de uma vez, sem for
print(precos_com_aumento)

print(f"Receita total de janeiro: {receita.sum()}")
print(f"Preço médio: {precos.mean():.2f}")
print(f"Maior preço: {precos.max()}")

Broadcasting é multiplicar um array inteiro por um único número — o NumPy aplica a conta em cada posição automaticamente. .sum(), .mean() e .max() já vêm prontos em qualquer array: somam, tiram a média e acham o maior valor sem precisar escrever um for. Receita total de Janeiro: 1965.0; preço médio: 34.83; maior preço: 150.0 (a Mochila).

⚠️ Quando o broadcasting NÃO funciona: arrays de tamanhos incompatíveis geram um erro real, não um resultado "estranho": 
a = np.array([1, 2, 3])
b = np.array([1, 2])
print(a * b)
ValueError: operands could not be broadcast together with shapes (3,) (2,)
Esse erro trava a execução — diferente da multiplicação de lista por número, que apenas produz um resultado errado sem avisar. Os dois arrays precisam ter o mesmo tamanho (ou um deles ser um único número).

2. Pandas: Series e DataFrame

🔗 Por que isso agora? Você acabou de ver o NumPy organizando números em arrays. O Pandas usa esses mesmos arrays por baixo dos panos, mas organiza os dados em tabelas — linhas e colunas com nomes — o formato que praticamente todo dataset do mundo real usa.

EstruturaO que é
SeriesUma única coluna de dados, com índice
DataFrameUma tabela completa, com várias colunas (Series juntas)

Exemplo 1 — Criando um DataFrame

import pandas as pd
from IPython.display import display

estoque_pequeno = pd.DataFrame({
    "produto": ["Caderno", "Lápis", "Mochila"],
    "preco_unitario": [12.5, 2.0, 150.0],
})

display(estoque_pequeno.head())
print(estoque_pequeno.shape)
💡 Por que display(...) em vez de print(...) pra DataFrame? print(df) funciona, mas devolve texto puro, sem a tabela com bordas que aparece normalmente num notebook. display(...) (de from IPython.display import display) manda o Jupyter/Colab renderizar a tabela completa. Regra prática pro resto da aula: display(...) pra DataFrame/Series; print(...) pra número, texto, array NumPy, lista ou dicionário.

Exemplo 2 — Lendo o dataset real (CSV)

import pandas as pd
from IPython.display import display

vendas = pd.read_csv("dataset/vendas_papelaria.csv")

display(vendas.head())
print(vendas.shape)   # (24, 5)

É assim que você vai carregar qualquer dataset real: com pd.read_csv("nome_do_arquivo.csv"). É o mesmo arquivo que a Seção 1 já leu com csv.DictReader — a diferença é que ali cada linha virava um dicionário separado, e aqui o Pandas já organiza tudo numa única tabela, pronta pra describe(), filtro e groupby() sem nenhum código extra de organização.

Exemplo extra — Series x DataFrame

precos_series = vendas["preco_unitario"]          # Series
precos_dataframe = vendas[["preco_unitario"]]      # DataFrame (mantém a estrutura de tabela)

print(type(precos_series))
print(type(precos_dataframe))
💡 Colchete duplo = mantém a estrutura de tabela. vendas["preco_unitario"], com um par de colchetes, devolve uma Series (pandas.core.series.Series) — uma coluna solta. vendas[["preco_unitario"]], com dois pares, devolve um DataFrame (pandas.core.frame.DataFrame) de uma coluna só. Selecionar mais de uma coluna sempre exige dois colchetes: vendas[["preco_unitario", "categoria"]].

3. Explorando um DataFrame: describe, filtros e groupby

Exemplo 1 — describe()

print(vendas.describe())

describe() resume, de uma vez, estatísticas de cada coluna numérica: count, mean, std (desvio padrão), min, max e os quartis (25%, 50%, 75%). É o primeiro comando que um analista roda ao abrir qualquer dataset novo.

⚠️ Veja como é um erro real do Python: se você digitar o nome de uma coluna errada, como vendas["preco_errado"], o Pandas recusa e mostra: 
KeyError: 'preco_errado'
Antes de selecionar uma coluna, confira os nomes exatos com vendas.columns.

Selecionando por posição ou por rótulo: .loc e .iloc

print(vendas.loc[0, "produto"])      # .loc: pelo nome da coluna + posição da linha
print(vendas.iloc[0, 0])             # .iloc: só por posição numérica (linha 0, coluna 0)
💡 .loc usa rótulos (nomes), .iloc usa posições (números). Os dois fazem a mesma coisa de jeitos diferentes. .loc continua funcionando mesmo que a ordem das colunas mude no arquivo, porque busca pelo nome; .iloc quebraria nesse cenário, porque busca só pela posição numérica.

Exemplo 2 — Filtro e groupby

# Filtro: só produtos vendidos mais de 40 vezes no mês
mais_vendidos = vendas[vendas["quantidade_vendida"] > 40]
print(mais_vendidos)

# groupby: preço médio por categoria
print(vendas.groupby("categoria")["preco_unitario"].mean())

Como o groupby pensa por dentro: Dividir → Aplicar → Combinar

EtapaO que acontece
1. Dividir (split)O Pandas separa as linhas em grupos, um para cada valor de categoria (Papelaria, Acessorios)
2. Aplicar (apply)Dentro de cada grupo separado, calcula a função pedida (ex.: mean() dos preços apenas daquele grupo)
3. Combinar (combine)Junta o resultado de cada grupo numa única Series de resposta
💡 groupby é o mesmo que uma Tabela Dinâmica no Excel: é exatamente isso que ela faz por trás dos panos. Acessorios (Mochila e Estojo) tem preço médio bem mais alto (92.5) que Papelaria (6.0) — coerente com mochila e estojo custando mais que material de papelaria simples.

Ordenando o resultado: sort_values()

preco_medio_por_categoria = vendas.groupby("categoria")["preco_unitario"].mean()
print(preco_medio_por_categoria.sort_values(ascending=False))

sort_values(ascending=False) ordena do maior valor pro menor. Com só 2 categorias a diferença parece pequena de ler, mas com 10 ou 20 categorias é a diferença entre procurar o maior número numa tabela inteira e ler direto a primeira linha.

4. Combinando tudo: receita por categoria

vendas["receita"] = vendas["preco_unitario"] * vendas["quantidade_vendida"]
print(vendas.head())

receita_por_categoria = vendas.groupby("categoria")["receita"].sum()
print(receita_por_categoria.sort_values(ascending=False))

vendas["receita"] = ... cria uma coluna nova: como ela ainda não existe, o Pandas simplesmente a adiciona, calculando cada linha como preço vezes quantidade — uma operação vetorizada que roda em todas as linhas de uma vez, com o NumPy por baixo fazendo a conta. Acessorios gera mais receita total (5890.0) que Papelaria (3855.0), mesmo vendendo muito menos unidades — o preço unitário alto compensa o volume baixo. É o contraste mais importante da aula: preço médio alto não é a mesma coisa que receita total alta.

Exemplo extra — Por dentro, uma coluna do Pandas é um array NumPy

receita_array = vendas["receita"].to_numpy()
print(receita_array)
print(type(receita_array))   # numpy.ndarray

print(f"Média via NumPy:  {np.mean(receita_array):.2f}")
print(f"Média via Pandas: {vendas['receita'].mean():.2f}")
💡 .to_numpy() converte uma coluna do Pandas num array NumPy puro — sem rótulos, só os valores. As duas médias saem 406.04, idênticas, porque são a mesma conta rodando duas vezes: o método .mean() do Pandas, por dentro, delega o cálculo pro NumPy. É a confirmação numérica de algo que a Seção 1 já antecipou: toda coluna de um DataFrame é, por dentro, um array NumPy.
